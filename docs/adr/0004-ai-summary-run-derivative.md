# AI Summary is a deletable run-derivative; file existence is the opt-in

We are adding an optional **AI Summary** (see [CONTEXT.md](../../CONTEXT.md)) — a
provider-generated (Anthropic or OpenAI) one-page narrative of an experiment's
analysis, embedded in the report. The question was how the summary, which is
generated by a paid external call, stays consistent with the analysis it
describes and how the user opts in.

## Decision

The AI Summary is generated **outside** report creation, from a new hub **AI**
card (its own `Category.AI`, between Scripts and Tools): a dialog offers a
curated provider/model list (only models known to accept image input;
last-used choice remembered in `ui.json`), runs the call in a `TaskWorker`,
writes `{name}_AI_Summary.txt` to `analysis/`, and automatically rebuilds the
report PDF. The AI option is offered only when a provider key is present in
`.env`; a runtime failure shows an error and never blocks a report build.

Coupling rules:

- **File existence is the opt-in.** `create_report()` embeds the summary as a
  labeled section (with provider/model/date provenance) iff the file exists.
  There is no AI checkbox on report creation.
- **`run_analysis()` deletes `{name}_AI_Summary.txt`.** The summary is a
  derivative of a single analysis run, like the plots and CSVs — except the
  pipeline cannot regenerate it for free, so deletion (not regeneration) is the
  staleness guard. The user regenerates from the AI card.

The AI input is the report's own ingredients — the serialized report model
(text blocks + figure PNG bytes as images) plus the small summary CSVs — never
the rendered PDF (the summary must exist before rendering) and never raw
per-frame tracking data (cost, and it would invite the AI to analyse rather
than summarize). The instruction prompt is an `ExperimentType` hook, like
`report_intro()`.

We chose a small in-repo provider layer (`AISummarizer` base with
Anthropic/OpenAI subclasses talking to the official SDKs, hard dependencies)
over reusing BioAI_Initiative's agent hierarchy: that stack (~2.6k lines,
Agents SDK, MCP, tool registries) serves multi-turn tool use, and its image
support — the one capability this feature needs — is absent for Anthropic and
vestigial for OpenAI.

## Consequences

- A stale summary can never appear next to fresh figures — the worst failure
  mode for a scientific document — at the cost of re-paying the API call after
  every re-run.
- Rebuilding a report is free and offline once the summary file exists.
- A regenerated summary costs one API call (~cents); accepted trade-off.
